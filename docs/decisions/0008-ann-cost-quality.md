# Decision 0008: quantify float32 HNSW cost and approximation loss

Status: predeclared before real-data ANN construction/search.

RRF reaches 55.27% validation known-Exact Recall@100 with exhaustive dense candidates. Benchmark one float32 HNSW graph family and a fixed search-depth grid. Use Faiss CPU 1.15.1 in a separate Python 3.12 environment (numpy 2.3.4, DuckDB 2.0.0), preserving every existing environment, encoder and source fingerprint. Required native wheels exist for the current Mac ARM64 and Linux x86_64. No int8 compression or serving layer is part of this increment.

Reuse all saved 1,814,924 product and 3,379 validation query vectors. Verify frozen reports, source hashes, query identities and vector/ID bundles. Build one `IndexHNSWFlat` per locale with inner product, **M=16, efConstruction=100, four build threads**, seed 20261102, insertion in the saved sorted-ID shard order. Persist each completed locale atomically with its row-aligned ID map and provenance/checksums. A committed locale may be reused after verification; incomplete construction may be rebuilt. Four-thread construction can be nondeterministic, so freeze the actual index and make no independent-build bitwise-reproduction claim. Never train or re-encode.

Use **efSearch 128, 256, 512**, top 100, and one CPU search thread. Report every point, without adding settings after seeing outcomes. Also persist the underlying vectors as an `IndexFlatIP` control using the same Faiss implementation. Float32 accumulation can differ from the earlier Torch control, so measure Flat's set agreement, known-Exact recall and RRF outcomes against the frozen Torch baseline separately. ANN agreement is primarily measured against this matched Flat control, not confused with human relevance.

Flat must honor score/ascending-product-ID ties even at the cutoff: overfetch and expand until the complete cutoff tie is included, or the locale is exhausted. ANN sorts its returned 100 by score/ID; unseen equal-score products remain approximation loss. Every integer neighbor must map to the correct locale and saved string ID; reject missing, duplicate or out-of-range neighbors. Record agreement@100 as the set intersection with exact top 100 divided by 100, per query, query-weighted overall and by locale. This is an approximation metric, distinct from known-Exact Recall@100 over incomplete human labels. Judgment coverage is not precision, and unjudged products remain unknown.

Compare singleton warm retrieval times in fresh workers, with one locale/index per worker and the same fixed shuffled query orders for every method. Warm the first 16 shuffled queries, then perform three full timed passes. Persist individual durations and p50/p95/p99 overall/per locale and per pass. Include native search, tie expansion and deterministic candidate sorting; exclude encoding, network/API, output serialization and file writes. Record load time and kernel maximum process RSS for each worker separately from build-worker RSS, source verification, evaluation/bootstrap and whole-command wall time. Index bytes include vectors/graph; do not equate serialized bytes with RSS or sum peaks into whole-host residency. Retain original raw-vector size. Do not compare old batched Torch time with singleton latency to claim a speedup; compare the matched singleton Flat and HNSW measurements instead.

Use the unchanged known-Exact/coverage metrics and paired 2,000 normalized-query-group bootstrap, seed 20261101. Replay the unchanged rank-only RRF, constant 60, BM25 window 100, final 100, substituting each ANN list. Report dense and hybrid changes against matched Flat and the frozen Torch dense/hybrid references, including per-locale regressions. Nominate the lowest efSearch only if agreement is >=95% overall and >=90% in every locale, and hybrid recall's paired lower difference bound is >=−0.5 percentage points overall, with no locale mean loss greater than 0.5 points versus matched Flat hybrid. Otherwise nominate none. This is a development budget, not a production SLO or final-test release. The finite validation grid is disclosed.

Before the full build, test native persistence/reload, identity/locale scope, exact cutoff ties including >100 duplicate vectors, negative scores, malformed outputs and the selection rule on tiny fixtures. CI uses only these fixtures in a separate CPU job; no real data or models. Require all existing tests. All three timed passes must return identical ranked outputs; repeat from fresh processes using the same frozen indexes and require identical result/metric hashes while retaining different latency observations. Record index/input hashes unchanged. Freeze sources before the full experiment and publish losing configurations, construction/storage cost, query memory/latency, approximation and hybrid quality, and replay evidence in a reviewable PR. Keep the official test unopened.
