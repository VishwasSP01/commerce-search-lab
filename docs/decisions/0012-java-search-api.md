# Decision 0012: bounded Java lexical search API

Status: declared before API implementation/real-sample verification.

Deliver one Java 21/Spring Boot **4.1.2** service in an independent `services/search-api` Maven project, using the repository's existing wrapper. The frozen root POM, locks, analyzers and experiment artifacts remain unchanged. Spring MVC and Jackson 3 handle HTTP/JSON; a reused JDK HTTP client calls the already verified local Elasticsearch profile. An official Elasticsearch client would add a generated API/dependency surface for one fixed query; reconsider it when the backend surface grows. No added spending.

`POST /v1/search` accepts exactly `query` (string), `locale` (`us`, `es`, `jp`) and optional integer `limit` (default 10, range 1–100). Reject unknown fields, wrong types, nulls, duplicate JSON keys, trailing JSON and blank normalized queries. Permit up to 256 Unicode code points before and after NFKC; cap the JSON body at 8 KiB. Analyzed-empty stop queries remain valid and return no hits. Query syntax stays literal. Return locale, requested limit, returned count, `retrieval=bm25`, and ordered `{productId,score}` hits. Scores are native ES scores; do not divide by 2.2 at this boundary. Product IDs remain strings.

Use the frozen pilot's title/locale/filter/sort/match settings, except the requested result size and a one-second Elasticsearch query timeout. Configure a concrete task-owned index (local default `csl-pilot-es-v1-c`) and loopback-only backend URL. The API defaults to `127.0.0.1:18080`. Backend connect timeout is 300 ms; a two-second full-response future deadline cancels the request on expiry. Cap backend response bytes at 1 MiB and concurrent backend calls at 16; no application retries or fallback. These are initial guardrails, not measured latency/capacity targets. Readiness uses the same bounded transport and permits backend absence at process startup.

The HTTP contract distinguishes invalid input (400), oversized body (413), unsupported media (415), timeout (504), backend unavailable/index missing/overload (503), and incomplete or malformed successful backend responses (502). Never return a partial list as a successful search or include raw backend errors/queries in error messages. Validate timeout/shard status, locale and ID consistency, finite nonnegative scores, uniqueness, cutoff and score/ID order. A versioned immutable backend index is an operational prerequisite; do not pretend response validation proves catalog membership without the offline catalog.

`GET /health/live` checks the Java process only. `GET /health/ready` checks green single-primary index health; it returns 503 when the backend/index is unavailable. This is local availability, not a check of every indexed product or corpus identity. Keep liveness healthy during backend failure.

Verification: real HTTP tests against a controllable backend cover JSON validation, normalization, locale isolation/query shape, limits, empty results, native score/string-ID preservation, unavailable/missing backend, slow headers/body, oversized/malformed/partial responses, and bounded overload/recovery. Compare every one of the 300 frozen sample queries at limit 100 with the saved ES ordered IDs/native scores; repeat at default 10 and explicit 1, keeping saved artifacts unchanged. Record report/source/JAR bindings, counts, mismatch details and graceful stop/restart of the Java process. CI adds module tests and extends the existing real-ES fixture job with packaged API verification against its tiny synthetic corpus. No dataset/model downloads in CI.

Close with documentation, focused commits and a reviewed/check-passing PR. Stop only task-owned Java/ES processes after testing, preserve the ES volume, and leave unrelated services alone. Full-catalog indexing, hybrid serving, circuit breakers, update ingestion, observability and load/recovery campaigns remain later increments. Official test labels remain reserved.
