# Decision 0011: bounded local Elasticsearch feasibility and lexical parity

Status: predeclared before indexing or searching the pilot corpus.

Move to serving feasibility after the closed ANN experiments. Use **Elasticsearch 9.5.6**, pinned multi-architecture image digest and checksummed analysis-kuromoji plugin. Run the free Basic license locally, with no cloud/trial dependency. One task-owned Docker Compose service uses **3 GiB memory, two CPUs, fixed 1 GiB JVM heap**, single-node discovery and loopback-only `127.0.0.1:19200`. Disable security only in this local profile, plus ML and GeoIP downloads. Docker Desktop's inspected VM has approximately 7.75 GiB; an unrelated PostgreSQL container must be left untouched. Stop only the pilot service after verification, preserving its project-scoped volume. Do not call this profile a production deployment.

The release bundles **Lucene 10.5.2**, whereas the frozen offline baseline uses **10.6.0**. Keep the frozen POM/code/locks unchanged and record this version difference. Elasticsearch's pinned `LegacyBM25Similarity` applies the `(k1+1)` boost factor. With k1=1.2, compare raw ES scores divided by **2.2** with offline BM25, absolute tolerance **1e-6**, relative **1e-5**. Keep native scores in evidence and do not tune a fitted scale. Score normalization is for comparison, not a hidden relevance change. Any unexplained ordering/analyzer drift is a result to report, not an excuse to edit the baseline after measurement.

Sample **10,000 metadata products per locale**, independently by SHA-256 of seed/TAB/locale/TAB/product ID, and **100 validation queries per locale** by the same rule using query ID. Seed is `commerce-elasticsearch-pilot-v1`. Preserve sorted locale/string product identity and sorted query IDs. Product selection must not use queries, labels or judged candidates. The 30,000-product corpus has its own statistics: do not compare its relevance scores with the 1.8M baseline or publish them as a new quality headline. The official test remains unopened.

Index the exact same normalized title sample through unchanged `CatalogCli` and Elasticsearch, using separate title fields by locale, BM25 k1=1.2/b=.75/discount_overlaps=true, one primary shard, zero replicas, explicit keyword locale filter and product-ID doc-value tie sort. Use English/Spanish analysis and a custom Japanese SEARCH tokenizer with the same baseform, POS-stop, CJK-width, Japanese-stop, katakana-stem and lowercase chain as the frozen analyzer. NFKC occurs client-side before both. Use literal `match` OR with `auto_generate_synonyms_phrase_query=false` (matching frozen Lucene QueryBuilder's default), `zero_terms_query=none`, no fuzziness, and no query-syntax interpretation. Keep top 100 without zero-match padding.

Before retrieval compare analyzer outputs for all 300 sampled queries, the first 30 sampled titles per locale, and a fixed small multilingual edge-probe set. Compare term text, absolute token positions, position lengths and UTF-16 offsets using a new package-access Java helper against the frozen analyzer. This probes selected strings, not all 30,000 document token streams. Capture empty streams explicitly. A separate tiny synthetic backend fixture checks case/width normalization, stop-only queries, literal punctuation, repeated terms, Japanese compounds and locale isolation without real data.

The parity target is **identical ordered product-ID lists and result counts for all 300 queries**, matching probe streams and normalized score agreement within tolerance. Validate server version, bundled Lucene, plugin, Basic/active license, single-node/shard health, exact document counts, no failed shards/timeouts/partial responses and catalog membership. Retain structured mismatches and do not hide unjudged or zero-result queries. A failed target prevents declaring parity but still completes a publishable diagnostic pilot. Existing full-catalog BM25/RRF and ANN decisions remain unchanged.

Bulk create deterministic locale-product IDs in bounded batches, reject every item-level error and refuse existing index names. Never blindly retry ambiguous writes or delete an unrelated index/container. Disable refresh while loading, then refresh/merge to one segment before comparison. Record node/JVM/plugin/image metadata, sample hashes, index bytes, load/query-batch durations, JVM heap and cgroup memory observations. Cgroup peak is container-lifetime usage, not isolated-run/whole-host RSS. HTTP batch timing is not a search-API p95/p99, concurrent QPS or update-freshness claim.

Test request/response validation, local-only endpoints/owned names, bulk partial failure, raw-score scaling, stable sample selection, graph analyzer transport and parity mismatch reporting. Keep required packaged tests and run a new small real-Elasticsearch CI fixture job without datasets/models. Run the real pilot twice into fresh owned Elasticsearch and Lucene indexes; require reproducible input/analyzer/retrieval/parity artifacts and decisions, while node/index IDs and resource observations may differ. Record startup/readiness and stop/restart health without claiming recovery of streaming updates. Finish with a reviewable PR and local runbook. Java/Spring API, dense/hybrid serving, Kafka/Flink and telemetry/load tests are separate increments.
