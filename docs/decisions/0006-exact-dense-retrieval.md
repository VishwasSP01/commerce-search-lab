# Decision 0006: measure exhaustive dense retrieval before approximation

Status: predeclared before scoring validation queries.

Reuse the completed 1,814,924 title embeddings. Encode only the 3,379 validation queries with the unchanged pinned multilingual E5 encoder, NFKC and `query: ` prefix. Retain max length 128, batch size 32, float32, masked mean and L2 normalization. Verify model files, encoding/source contracts and validation checksum; never open the official test set. Record query truncation and norms. Keep the frozen pilot/export sources and dependency locks unchanged; use their existing environment.

Search every product in the query's locale with exhaustive CPU float32 inner products, using four PyTorch threads. Normalized inner product approximates cosine to the recorded normalization/rounding tolerance. “Exact” means no ANN candidate loss; it does not mean infinite-precision arithmetic or exhaustive human relevance. Stream one existing product shard and at most 128 queries per score matrix. Retain a running top 100 per query; discard no product before scoring. Verify every shard's payload, row-aligned ID map, checksum, norms, strict identity order, locale and final sequence digests against the completed export. Do not re-encode products or build an ANN index in this increment.

Rank by descending computed score and then ascending product ID. Partition selection alone is unstable: explicitly include all products equal to the cutoff score before resolving ties by ID, including at shard merges. Negative scores are valid. Return 100 results whenever the locale has at least 100 products; do not apply lexical token-count or positive-score constraints. Persist query inputs, vectors, ranked results, per-query metrics and hashes under ignored data. Retrieval accepts query identity/text and vectors, not judged candidates. Evaluation follows retrieval.

Keep the full-catalog BM25 metric definitions: query-mean known-Exact Recall@100, null/excluded if no known Exact; judgment coverage over actual returned top ten, empty convention zero; also report empty/short lists and slot fill. Unknown relevance remains unknown. Do not report catalog NDCG with unknown labels treated as Irrelevant. Verify exact query identity/group/label-denominator coverage against BM25's saved evidence. Use the same 2,000 group-bootstrap resamples and seed 20261101 for marginal intervals and paired dense-minus-BM25 intervals, overall and per locale. Include equal-locale macro means. No significance p-value or final-test claim is part of this increment.

Test exhaustive/blockwise agreement, ties across blocks and at the cutoff, negative scores, corruption/identity mismatch, locale isolation and malformed/incomplete metric inputs with small fixtures. Require unchanged existing tests. Run twice into fresh output directories, including fresh query encoding, and compare query vector/result/per-query hashes and all metric intervals. Record runtime/backend, query encoding, search work, verification, total main wall time, kernel process max RSS and raw storage. Batch timing is not API latency or QPS; MPS allocation observations are not whole-host/GPU peaks.

Publish the measured outcome, including regressions. Dense gain is a hypothesis; keep BM25's 50.29% known-Exact Recall@100 as the comparator regardless of outcome. Commit implementation and evidence in focused commits and push a reviewable PR. Fusion and ANN/quantization remain separate milestones.

Implementation references: [PyTorch 2.9 matrix multiplication](https://docs.pytorch.org/docs/2.9/generated/torch.mm.html), [NumPy 2.3 unstable partition selection](https://numpy.org/doc/2.3/reference/generated/numpy.argpartition.html). The pinned model card and encoder contract are already saved with the pilot.
