# Decision 0007: one fixed fusion of the saved lexical and dense lists

Status: predeclared before computing fusion results.

The exhaustive dense experiment did not demonstrate an overall gain. Test whether its candidates complement BM25 by fusing the existing full-catalog result lists. Use equal-weight reciprocal rank fusion with **rank constant 60**, source windows **100**, and final cutoff **100**. For each product sum `1 / (60 + rank)` over lists containing it; source ranks start at one and absence contributes zero. Ignore raw retrieval scores during fusion. Accumulate and sort exact rational scores, then ascending product ID for ties, and serialize binary64 scores. Product identity is scoped by query locale. Do not sweep constants, weights or candidate depths after observing results. This follows the [documented RRF formula](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion); no Elasticsearch serving implementation is claimed.

Reuse only the saved, checksummed BM25 and dense validation lists. Verify report/source bindings, query-input identity, the validation partition and all required input artifact hashes. Reproduce each source's per-query metrics and require identical query/group/known-Exact denominator coverage before comparison. BM25 can have empty/short lists; dense supplies 100 products per query, so fusion must return exactly 100 unique products. Fuse identities/ranks without passing labels or judged candidates to the fusion function. Verify output membership in the source union. No re-encoding, catalog scan or new search is needed.

Retain known-Exact Recall@100 and judgment coverage among actual returned top ten, unknown labels remaining unknown. Report short/empty lists, slot fill, query-weighted overall/per-locale means and equal-locale means. Compare RRF with **both** BM25 and dense using 2,000 paired percentile bootstrap resamples of locale-normalized query groups, seed 20261101; also report marginal intervals. Intervals are validation-development diagnostics without multiplicity adjustment or p-values. Do not turn incomplete judgments into a catalog NDCG headline or assume lower coverage means lower precision.

Freeze the **78 original vocabulary-gap queries** from `bm25-error-analysis-v1` where `zero_kind=no_title_token_overlap`, verifying the saved diagnostic checksum and complete query identity coverage. This cohort had no title-token overlap among judged candidates; it is not a claim that BM25 returned no catalog matches. Report each source's and RRF's recall/coverage for this cohort and by locale, and query-level counts of new/lost known Exact products relative to BM25. Define a zero-hit recovery as a query with no known Exact in BM25 top 100 but at least one in RRF top 100. Distinguish any new Exact product from a net recall improvement. Do not say a query is completely “fixed” because a score became positive or one product was recovered.

Measure known-Exact coverage in the union of the two top-100 lists (up to 200 unique products) and how many available known Exact products fusion drops at its final cutoff. This is a candidate-opportunity diagnostic, **not a third Recall@100 method**. Publish overall and per-locale addition/loss counts and the fixed-cohort diagnostics so a gain cannot conceal regressions or cutoff loss.

Nominate RRF as the next offline development reference only if the overall recall paired lower interval is positive against both single methods and no locale mean recall decreases versus BM25. Otherwise retain BM25 as the baseline and publish the tradeoff. This conservative rule is a development decision, not a final-test release, production rollout or requirement for experiment completion. Unknown relevance and the repeatedly inspected validation set limit generalization.

Test the formula against hand calculations, missing-list behavior, duplicate/rank rejection, score-scale independence, locale isolation, ties at the cutoff, actual known-Exact additions/losses and incorrect query/group pairing. Run twice into fresh directories; compare all ranked/metric/diagnostic hashes, intervals and decisions. Record fusion-only time, input verification/evaluation wall time and process RSS separately; cached-list fusion does not measure end-to-end hybrid search latency or serving memory. Keep datasets and detailed rankings ignored, frozen sources/locks unchanged and the official test unopened. Commit a compact report, losing results if any, reproduction evidence and a reviewable PR.
