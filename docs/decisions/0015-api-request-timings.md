# Decision 0015: versioned API/backend timing instrumentation

Status: declared before implementation and diagnostic measurements.

Version the existing independent API module from0.1.0 to **0.2.0**. Preserve the exact tested0.1.0 JAR under ignored `data/reference/search-api-0.1.0`, bound to the baseline load report/source commit. Old configs/reports/experiment scripts stay unchanged; reproduce an old runtime from its Git ref/worktree and archived JAR. Earlier current-source/JAR guards correctly reject0.2.0 until a new versioned experiment explicitly chooses it. Do not duplicate the service or rewrite previous benchmark provenance.

Add Boot-managed Actuator/Micrometer and Prometheus exposition at loopback `/actuator/prometheus`; expose only health/prometheus. Preserve query construction, scoring, response bodies/statuses, timeouts, heap256MiB and ES3GiB/twoCPUs/1GiBheap. Keep a bounded set of timer/gauge labels: operation, fixed stage, outcome, locale/status. IDs/query strings/product IDs/URLs are never metric labels. Enable Tomcat MBean metrics for busy/max threads; these do not directly measure queue occupancy.

Time **POST /v1/search** from servlet-filter entry through synchronous MVC serialization using `System.nanoTime`. Generate a fresh server UUID, return `X-Request-ID`, propagate it as ES `X-Opaque-Id`, and clear thread-local timing context on every success/error path. Ignore caller-supplied IDs. Keep per-request JSON timing events **off by default**, enable for the diagnostic. Events contain only correlation ID, bounded outcome/locale/status and numeric durations, not query text, bodies, results or product IDs. Metrics remain active when events are disabled.

Time backend operation totals, request construction, full-response wait, JSON decoding and result validation separately, including timeout/error paths. Preserve nullable/missing values rather than report an unmeasured step as zero. ES `took` is a separate integer-millisecond server observation that includes its search queue/execution and excludes request transit/JSON response serialization/return transit. It is not pure compute time. Do not sum nested timers or subtract aggregate percentiles. The servlet timer excludes pre-filter connector/worker queues; client-minus-filter **paired duration residuals** include client/connect/network/dispatch/measurement resolution and must never be labelled Tomcat queue time.

Verify the existing API/failure contract with the new module; add tests for concurrent correlation/context cleanup, success/invalid/timeout/error timer counts, ES opaque-ID propagation, absence of query/ID metric labels, and Prometheus exposition. Test controlled delays in HTTP/body/JSON phases. Every request outcome must remain visible even when no backend call occurs. A failed request must not leak stale context into a reused worker. Best-effort event serialization/logging must not change an otherwise correct response.

Use the frozen **300-query workload** from api-load-v1 unchanged, with exact expected native results. Keep a separate all300-query functional check through0.2.0 at100/default10/1 against the saved full-catalog output, after the bursts so it does not intentionally prime the cohort before the first diagnostic. Run **four** fresh-Java startup-like bursts at100 arrivals/s for30s, 64VUs and3sclient deadline, order **0.2,0.1,0.1,0.2**. Restart only the owned ES service and wait for green shard health before every burst; keep OS caches untouched. No pre-search warm-up. These are new instrumented diagnostic observations, not edits/repeats of the closed load baseline. Sampling/logging and cache/order history can affect timing; do not estimate causal instrumentation overhead or claim to prove the historical807ms spike's root cause.

For0.2.0 correlate client log events with local server JSON events by generated ID and reconcile client events against raw metric multisets; independently recompute paired summaries, slowest-request examples, stage coverage and scrape counters. Capture Prometheus before/after, including automatic JVM/HTTP/Tomcat meters, plus existing k6 offered/started/dropped/failure accounting. Paired residuals can be negative within resolution/response-finalization effects; retain them. Transport attempts without returned IDs and unmatched server events stay explicitly unmatched; never invent an identity. IDs occur in local event files, not Prometheus/k6 metric tags. A historical spike need not recur: report what boundaries show and what remains unknown. Keep raw IDs/events/workload outside Git; aggregate only anonymized numeric summaries. Stop further bursts on incorrect results/process/monitor failure and preserve evidence.

CI keeps the four jobs: packaged API metrics/correlation tests and tiny real-ES diagnostic fixture, without real datasets or production load rates. At completion stop task-owned processes, preserve volume and leave unrelated services alone. Publish a reviewable PR with reference/new hashes, test results and limitations. OpenTelemetry export, collector/Grafana dashboards, direct connector queue timing, performance fixes and higher-rate tests are separate increments.
