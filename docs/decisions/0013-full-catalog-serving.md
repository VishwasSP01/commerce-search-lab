# Decision 0013: full-catalog lexical serving feasibility

Status: predeclared before full-catalog Elasticsearch indexing/searching.

Reuse the immutable, verified 303,680,512-byte title export containing **1,814,924 locale-product records** and the **3,379 validation queries** from the full-catalog Lucene baseline. All queries were audited for API eligibility: none exceed its bounds or normalize to blank. Keep the official test reserved. No re-encoding or catalog expansion.

Keep Elasticsearch 9.5.6/Kuromoji, Lucene 10.5.2, two CPUs, 3 GiB container/1 GiB heap, local Basic license, frozen title analyzers/BM25/query construction and the existing Java API JAR. The offline reference remains Lucene 10.6.0. API requests select a concrete new `csl-pilot-catalog-v1-*` index through configuration; no Java implementation/default or frozen experiment source changes. API heap stays 256 MiB. Python uses bounded export batches and must stop on observed peak RSS over 1 GiB. Require at least 10 GiB free disk. No envelope increase inside this experiment.

Stream sorted locale/string-ID/Base64-title records; reject malformed/duplicate/unordered input and verify all existing export/input/source hashes before writes. Bulk **create**, at most 500 documents/1 MiB per request, bounded sequential pressure, validate every item, no blind retries. Refuse existing index names. Stop indexing after 30 minutes. Disable refresh during load, then refresh, block writes, run one asynchronous one-segment force merge with a ten-minute polling deadline, flush and verify counts per locale, no deletions, one segment and green primary health. Force merge is for this immutable comparison, not a proposed live-update operating policy.

Compare analyzer terms/positions/lengths/offsets for all 3,379 queries, first 30 export titles per locale and nine fixed edges (**3,478 probes**). Search every query at top100 and validate returned locale-catalog membership and complete response semantics. Target exact ordered IDs/counts against frozen full-catalog Lucene, with the already declared raw-ES `/2.2` score comparison and tolerances. Publish every mismatch and actual incomplete-label metrics using the frozen metric implementation, even if parity fails. Matching finite probes does not establish universal version equivalence; do not change the baseline or fit a correction.

Run the unchanged packaged API on the full index. Check all queries at limit100/default10/1 against native ES, preserving raw scores. Two fresh builds repeat analyzer/retrieval/parity/per-query metrics and API artifacts. Restart only the owned ES service before each build, preserving its volume, so cgroup lifetime peaks start afresh. Keep old sample/fixture indexes and disclose that their memory/storage also exists in the node. Capture all task-owned index UUIDs/document inventory, index bytes, batch/merge/API durations, observed JVM heap and cgroup current/peak every five seconds, plus Python process peak RSS. Cgroup peak includes native/cache and the node's other indexes; heap maximum is a sampled observation. Batch timings establish no API QPS or latency percentile claim.

Require identical fresh-build artifacts and decisions for a reproducibility claim. Preserve all failure evidence; do not automatically delete indexes or restart a failed write. An exhausted merge deadline leaves the uncancellable ES task visible for inspection rather than launching a duplicate merge. Final verification gracefully restarts the backend on its volume and requires both index UUIDs/counts and all top100 API outputs to persist. Stop owned Java and ES processes afterward; leave unrelated services and Docker Desktop alone.

Add small tests for streaming identity validation, byte/document limits, partial bulk failure, asynchronous task failure/deadline and persisted-count checks. Extend the existing native ES CI job with a tiny immutable-loader fixture, without real datasets. Complete with aggregate reports, a runbook and a check-passing PR; failed parity/resource targets are publishable outcomes. Load, telemetry, circuit breakers, neural serving and updates are separate increments.
